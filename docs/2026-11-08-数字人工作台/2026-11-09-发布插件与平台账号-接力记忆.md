## 2. 架构要点（当前实态）

### 2.1 独立 publish-studio

- 路径：`dsh-newapi-fork/publish-studio/`
- Cordis：`export const inject = ['webServer']`；`ctx.provide('publishStudio', api)`
- **bundles 顺序**：`publish-studio` 必须在 `digital-human-studio` **之前**（提供方先加载）
- 数字人桥：`digital-human-studio/src/publish-studio-bridge.ts` → `configurePublishStudio`；启动日志应有 `publish-studio bridge connected (independent plugin)`
- HTTP（宿主认证 + same-origin）：
  - `/publish-studio/management`
  - `/publish-studio/confirmation`
  - `/publish-studio/login-qr`（仅真实探测到 QR 才有图）
- 数字人转发入口：`POST /digital-human-studio/publication-management`（`studio.*` 动作映射到 publish-studio）

### 2.2 UI 入口

- 左侧工作台「发布」页 + **公司右侧竖菜单**（档案/素材/…/发布包/**平台账号** 等）
- **平台账号页**：`DigitalHumanPlatformAccounts`（`ui-settings-account`）
  - 添加已白名单平台 → 登录/扫码 → 轮询状态 → 本公司绑定/移除（移除需确认，**不**注销平台账号、不删媒体）
- 发布管理：展示已绑定摘要并引导至「平台账号」；已清理「尝试从原 GEO 列账号」类失效入口
- 前端产物：`deepseek-harness/packages/client/ui-settings-account/lib/client.js`（link 进 web profile 后硬刷新可取新 bundle）

### 2.3 平台登录（设计语义）

- 白名单：`publish-studio/publishing/login-platforms.json`（约 **21** 个；方法均为 `browser_official_login`）
- 执行器：`publishing/login_runner.py`（Playwright headed 打开官方 `login_url`）
- **成功判定**：离开登录页且可达 `personal_url`（如有）并写入本地 `storage_state`；**关闭窗口 ≠ 成功**
- 仅当页面真实存在二维码节点才经 `/publish-studio/login-qr` 展示；否则提示在受控窗口完成登录
- 启动失败时**不得**文案假装「已打开官方浏览器」；依赖未就绪时 UI 显示精确缺项
- 动作：`studio.accounts.platforms|list|create|login.start|poll|cancel|remove`  
  AI 只读 `platforms/list`；**不可** start/approve/execute

### 2.4 授权 / 额度（与平台登录区分）

- 插件许可证登录（aid/authBase/额度基线）**≠** 抖音/小红书等平台登录
- 未配 license / 未确认额度基线时：`runtime.enabled=false` 可挡住**真实发送**；**不应**因此挡住账号查看与登录准备
- 真人确认：nonce + CSRF + 媒体 revision；未知结果不重试；AI 不能拿到确认入口

## 4. 本轮已完成：账号登录入口 + 依赖自动安装

### 4.1 账号登录通路（可点击，非 dummy）

- 右侧「平台账号」已接线到真实 `studio.accounts.*` 与 login runner
- 状态机：未登录 / 等待浏览器或扫码 / 已授权 / 过期 / 失败 / 取消
- 自动化测试以 **mock transport / mock runner** 验证；**未**在本轮做全平台真实扫码验收

### 4.2 运行时自动准备机制

| 项 | 说明 |
|----|------|
| 触发 | `publish-studio/package.json` 的 **`prepare` + `postinstall`** → `scripts/ensure-runtime.mjs` → `publishing/ensure_runtime.py` |
| 固定版本 | `publishing/requirements-runtime.txt`：`playwright==1.52.0`（及 loguru/requests 销钉） |
| 隔离位置 | `~/.dsh/publish-studio/runtime/venv` + `.../runtime/ms-playwright` + `status.json` |
| 浏览器 | 仅装 Chromium；`PLAYWRIGHT_BROWSERS_PATH` 与 venv **同套** |
| 幂等 | 已 ready 且探针通过则跳过下载 |
| 探针 | 隔离 Python **headless** 打开 `about:blank`（非真实站点登录） |
| 诚实失败 | 安装失败写 `ready=false` + `missing`；不伪装成功；不 sudo |
| ignore-scripts | 若宿主禁用 install scripts，`prepare/postinstall` **不会执行**；启动日志与 `studio.runtime.deps` / 平台账号页须显示未就绪；可手动：`node scripts/ensure-runtime.mjs` |

**重要限制（部署必读）**：

1. **首装需要网络**下载 Playwright Chromium；**不是**把浏览器包完全打进仓库的离线包。  
2. 目标机器需要可用的 Python（本机曾用 `~/.local/bin/python3.12` 作 bootstrap 创建 venv）。  
3. **跨系统未验收**（当前实装与探针在本机 macOS arm 完成）。  
4. 系统用户目录里旧的 `~/Library/Caches/ms-playwright/chromium-1208` 缺失问题，已改为走隔离 runtime，不再依赖用户 site-packages 的错配版本。

本机曾验证（历史事实，非永久 PID）：

- `status.ready=true`，`probeOk=true`，`browsersReady=true`
- Python：`~/.dsh/publish-studio/runtime/venv/bin/python`
- 浏览器目录：`~/.dsh/publish-studio/runtime/ms-playwright`（例：chromium-1169）

## 5. 进程与重启纪律

- Web 工作台：**3080**；用 `scripts/start-web.sh` 定向持久重启。  
- **PID 只是历史快照，下一次操作前必须重新 `lsof`/`ps` 核对，禁止盲用旧 PID。**  
  - 历史参考（Asia/Shanghai）：启用 publish-studio、加载平台账号路由、加载隔离 runtime 等轮次曾出现过不同 PID；均已被后续重启替代。  
- **3000 / 9001 / 原 GEO：本发布能力轮次未改、未当发布依赖去启动。**  
- 仅前端 bundle 变更时往往硬刷新即可；**后端新路由 / runtime 解析 / login-qr** 需重启 3080 后才加载。  
- 未授权不得重启；用户确认后才执行定向重启。

## 7. 安全与 AI 边界（保留）

- AI：可 overview / list packs / calendar / tasks / prepare；**不可** approve、execute、代为平台登录  
- 确认发送：仅 UI confirmation + humanAction（nonce/CSRF）  
- 未知结果不重试；媒体 revision 变化需重准备  
- 账号移除：只删本公司绑定与本地授权文件，不撤平台号、不删媒体  
- 输入白名单 / 路径受控 / 本机宿主认证 / same-origin；不把「给 AI 控制浏览器或读任意文件」能力放开
